What is Vibe Coding?

"Vibe Coding is a style of programming where you fully embrace AI assistance — describing what you want in natural language and letting the AI generate code, while you guide, iterate, and refine."

  • Conversational approach to software development
  • Human provides intent, context, and direction
  • AI handles syntax, boilerplate, and implementation details
  • Focus shifts from "how to write" to "what to build"

The Origin Story

"There's a new kind of coding I call 'vibe coding', where you fully give in to the vibes, embrace exponentials, and forget that the code even exists."
— Andrej Karpathy, February 2025
  • Coined by former Tesla AI Director & OpenAI founding member
  • Sparked massive industry conversation

The Tech Stack Behind Vibe Coding

🧠 Large Language Models

Foundation models (GPT-4, Claude, Gemini) trained on billions of code samples. They predict the next token based on context — essentially very sophisticated autocomplete.

Input: "function add(a, b) { return"
Model predicts: a + b; }

📊 Embeddings & Vector Search

Code is converted to numerical vectors capturing semantic meaning. Similar code clusters together, enabling "find code that does X" without keyword matching.

"parseJSON" → [0.2, -0.5, 0.8, ...]
"decodeJSON" → [0.21, -0.48, 0.79, ...] // Similar!

🔄 RAG (Retrieval-Augmented Generation)

Instead of fine-tuning, RAG retrieves relevant code from YOUR codebase at query time and injects it into the prompt. This is how Cursor "knows" your patterns.

Query: "Add error handling"
RAG finds: your existing ErrorBoundary.tsx

🌊 Streaming & Token Windows

Responses stream token-by-token for instant feedback. Context windows (8K → 128K → 1M) determine how much code the model can "see" at once.

GPT-4: 128K tokens ≈ 100K words
Claude: 200K tokens ≈ 150K words

Agentic AI: The Next Level

From autocomplete to autonomous coding

What is Agentic AI?

An AI that can autonomously plan, execute, and iterate on multi-step tasks — not just respond to single prompts.

  • Goal-oriented: Understands the end objective
  • Multi-step: Breaks down complex tasks
  • Tool use: Reads files, runs commands, edits code
  • Self-correcting: Sees errors, fixes them

Cursor Agent Mode

1 Reads your codebase & understands structure
2 Creates a plan for multi-file changes
3 Edits files, creates new ones as needed
4 Runs terminal commands (npm, git, tests)
5 Sees errors → iterates until it works

Example: "Add authentication to my Express app" → Agent reads routes, adds middleware, creates auth files, installs packages, tests it

Example: From Prompt to Code

Good Prompt → Better Prompt

🔴 Good Prompt

"Create a password strength checker function in TypeScript. It should return weak/medium/strong based on: length (min 8), uppercase, lowercase, numbers, and special characters. Include unit tests."

Generated Output

export function checkPasswordStrength(pw: string) { let score = 0; if (pw.length >= 8) score++; if (/[A-Z]/.test(pw)) score++; if (/[a-z]/.test(pw)) score++; if (/[0-9]/.test(pw)) score++; if (/[^A-Za-z0-9]/.test(pw)) score++; return score <= 2 ? 'weak' : score <= 4 ? 'medium' : 'strong'; }

⚠️ Works, but lacks validation and clear strength rules

🟢 Better Prompt

"Create a TypeScript function named `passwordStrength(password: string): "weak" | "medium" | "strong"`. Rules: - Minimum length considered: 8 characters. - Strength rules: - weak: length < 8 OR matches fewer than 2 of: uppercase, lowercase, digits, special chars. - medium: length >= 8 AND matches exactly 2 or 3 of the 4 character classes. - strong: length >= 8 AND matches all 4 classes. - Special characters = any non-alphanumeric ASCII (e.g. !"#$%&'()*+,-./:;<=>?@[\]^_`{|}~). - Function must validate input type and throw `TypeError` for non-string inputs. - Export as a named export. Also include unit tests using Jest (TS), covering normal cases and edge cases (empty string, all-lowercase long password, missing input, long password with unicode). Include a `package.json` test script."

Generated Output

export function passwordStrength( password: string ): "weak" | "medium" | "strong" { if (typeof password !== "string") throw new TypeError("Input must be a string"); if (password.length < 8) return "weak"; const classes = [/[A-Z]/, /[a-z]/, /\d/, /[^A-Za-z0-9]/] .filter((r) => r.test(password)).length; if (classes < 2) return "weak"; return classes < 4 ? "medium" : "strong"; } // ✓ Jest tests + package.json included

✓ Type-safe ✓ Validation ✓ Clear rules ✓ Tests

💡 Better prompts = Better code. Be specific about types, validation, edge cases, and tests.

Challenges & Considerations

⚠️ Watch Out For

  • AI hallucinations - confident but wrong
  • Security vulnerabilities in generated code
  • Over-reliance reducing core skills
  • Context limits with large codebases
  • Intellectual property concerns
  • Inconsistent code style

✅ Mitigations

  • Always review & understand generated code
  • Run security scans & tests
  • Keep fundamentals sharp
  • Provide clear, focused context
  • Use enterprise-approved tools
  • Establish team conventions

Where Vibe Coding Falls Short

Know the limits to use it effectively

🚫 Complex State Machines

AI struggles with intricate state transitions, race conditions, and multi-step workflows. Often generates incomplete or buggy state logic.

🐢 Performance-Critical Code

AI frequently writes O(n²) when O(n) exists. Misses caching opportunities, creates memory leaks, ignores algorithmic efficiency.

🏢 Deep Domain Context

AI doesn't know your proprietary systems, internal APIs, business rules, or why that "weird" legacy code exists. Context windows have limits.

🏗️ Multi-File Architecture

Large refactors across many files often fail. AI loses track of dependencies, creates circular imports, breaks existing contracts.

Takeaway: Use AI for acceleration, not abdication. The harder the problem, the more human judgment matters.

Best Practices for Engineers

  • Be Specific: "Create a React hook for debounced search" > "Make search work"
  • Provide Context: Share relevant code, types, and constraints
  • Iterate Incrementally: Build complex features in smaller steps
  • Verify Everything: Test generated code, check edge cases
  • Learn From Output: Understand why the AI made certain choices
  • Know When NOT to Use: Security-critical code, proprietary algorithms
  • Document Your Prompts: Good prompts are reusable team assets

Golden Rule: AI is a power tool, not autopilot. You're responsible for what ships.
